# dsh-session-temp-reaper

[English](README.en.md) | 中文

给 DSH（DeepSeek Harness）聊天界面加一个按钮：**一键清理本次会话产生的临时文件**。

按钮在输入框左侧。点开后插件扫描本会话写过、跑命令写出、以及落在临时目录里的文件，列成一张可勾选的清单。**勾 = 删除**，没勾就是保留。删除前要点两次，删完给你一份结果。

## 为什么不是「按时间猜哪些是临时」

一开始就是那么做的，结果把别的会话的交付物、插件源码统统扫进来，还让模型给出「可以删」的结论 —— 真正会毁东西的那种错误。

现在改成 **模型自己登记**：

- 插件注册了一个工具 `mark_temp_files`，模型（我）在写临时脚本、调试产物、一次性中间文件时主动调用它
- 系统提示里也有一节 `## Temporary files` 提醒模型这么做
- 面板分两组：**模型标记的**（默认勾上）和 **未标记的**（折叠，默认保留，只作参考）

启发式扫描没有删掉，它现在只负责「喂未标记那一组」，不再决定默认勾选状态。

## 功能

- 输入框左侧按钮，面板浮在输入框上方；Esc 或点外面关闭
- 两组清单：标记组默认勾选，未标记组折叠且默认不勾
- 每行显示类型、来源徽章（会话写入 / 指令写入 / 未确认归属 / 系统临时 / 临时目录）、大小、时间和说明
- 交付物（`present` 出来的文件、可交付记录）和「正在被 profile 使用的插件/依赖」即使被标记也**不勾**
- 来源徽章之外的额外提示：`已交付`、`正在使用`
- 「问模型」按钮：把当前清单塞进输入框草稿并提交，让模型说明每个文件干什么用、哪些能删 —— 只问，不删
- 「全部保留 / 全部删除」批量切换，删除按钮两次点击确认，5 秒后自动复位
- 中英双语，跟随 DSH 语言设置

## 安装

### 本地链接（开发用）

```bash
# 假设 profile 在 ~/.dsh/profiles/desktop
cd ~/.dsh/profiles/desktop
npm install --save "link:<本项目绝对路径>"
```

然后在同一个 `package.json` 的 `dsh.profile.bundles` 数组里加上 `"dsh-session-temp-reaper"`，重启 DSH。

### 从 GitHub 装

```bash
cd ~/.dsh/profiles/desktop
npm install --save "github:Kaalia0912/dsh-session-temp-reaper"
```

同样记得把包名加进 `dsh.profile.bundles`。

改完 Host 代码（`index.js`）需要重新加载模块：在 GUI 里把插件关掉再打开（`plugin_manager` 的 `set_plugin`），或者重启 DSH。只改 `client.js` 的话刷新页面即可。

## 使用

1. 点输入框左侧的清理按钮 → 扫描
2. 看标记组：该删的默认已经勾好了；想留哪个就取消勾选
3. 拿不准就点「未标记的文件 N 个」展开看有没有漏网的，要删就手动勾
4. 点「删除 N 个」→ 再点一次确认
5. 面板显示「已删除 X 个，失败 Y 个」

## 模型侧的工具

```js
mark_temp_files({
  paths: ["scripts/probe.mjs", "out/report.tmp"],  // 相对 cwd 或绝对路径
  note: "调试用的临时脚本"                          // 可选，显示在面板里
})
```

返回 `Marked N temporary file(s).`。标记只写进会话日志（一条 `tool/call`），没有额外状态文件，所以换机器、换 profile 也随会话一起走。同一会话里重复标记同一个文件是幂等的。

**不要标的东西**：用户要的交付文件、改过的既有源码。标了也会被 `present`/依赖根保护挡住，但那属于兜底，不是设计意图。

## HTTP 接口

两个同源 POST 路由，客户端按钮用它们和 Host 通信：

| 路由 | 请求 | 响应 |
| --- | --- | --- |
| `/session-temp-reaper/scan` | `{ sessionId }` | `{ cwd, items[] }` |
| `/session-temp-reaper/delete` | `{ sessionId, paths[] }` | `{ results[], removed }` |

扫描结果在 Host 内存里缓存 10 分钟；删除只接受「该会话最近一次扫描里出现过的路径」，跨会话、凭空构造的路径一律拒绝。

## 安全边界

- **只删扫描过的**：`paths` 必须在本次会话的扫描结果里，否则逐条报错
- **限定根目录**：文件必须位于会话 cwd、本会话的 spill 目录、或命令显式写到 OS 临时根下的文件；spill 目录只有本会话那一个能整目录删
- **交付物保护**：`present` / 交付记录里的文件永远默认保留
- **依赖保护**：profile 依赖包解析出的真实目录（比如插件被 `link:` 进 profile）里的文件默认保留
- **`.git` 永不出现**：任何含 `.git` 段的路径直接跳过，不列也不删
- **两次点击**：删除按钮第二次点击前不会发请求
- **不自动删**：插件从不主动删除任何东西，只有你点确认才动

## 扫描范围（未标记组的来源）

| 来源 | 含义 |
| --- | --- |
| `session` | 模型用 `write` / `edit` 直接写的文件 |
| `command` | 命令里显式写出的路径（重定向、`Set-Content` 等） |
| `scan` | 文件创建时间落在本次会话某条 shell 命令之后 15 分钟窗口内，或会话开始后出现在工作区根目录 —— 归属未完全确认 |
| `external` | 命令写到 OS 临时根下的文件 |
| `spill` | 本会话的 `dsh-spill-*` 目录，整目录列一条 |

事件窗口取会话日志最后 72 小时；工作区遍历上限 1500 个文件 / 20000 个目录项 / 12 层深；跳过 `node_modules`、`dist`、`.git` 等目录。

## 已知限制

- 模型忘了调 `mark_temp_files`，标记组就是空的 —— 这时候只剩未标记组可看，不会误删
- 并发会话同时写同一工作区时，`scan` 来源的归属靠时间窗口推定，面板会标「未确认归属」
- 只写在 `cordis.patch.yml` 里、没进 profile `dependencies` 的包，识别不出「正在使用」
- 删除不可恢复，没有回收站
